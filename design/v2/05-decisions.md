# RubyUI 2.0 — Phase 1 gate: decisions and deviations from the plan

Date: 2026-09-07
Status: living — one line per deviation from `design/v2/03-plan-fase1.md`, with the reason. Appended as the gate progresses.

Scope executed so far: **Phase 0 (day 1) and Phase 1 (days 2–3, Dialog)**, in `experiments/v2-gate/`.

## Premises stated at the start

- **"Phase 1" read as the plan's inner Phase 1 (days 2–3: Attributes, layer, Dialog), with Phase 0 (day 1) executed as its prerequisite** — Phase 1's acceptance ("6 `dialog/` snapshots byte-identical on both lanes") is not verifiable without the lanes, the parity runner and the probes Phase 0 builds. Phases 2–6 untouched.
- **This file lives at `design/v2/05-decisions.md`, not `docs/v2/05-decisions.md`** — `docs/` is the Rails app behind rubyui.com and has no `v2/`; `design/v2/` holds the charter and the plan this file annotates.

## Deviations

1. **`rails new` got `--skip-active-record`, `--skip-bundle`, `--skip-git` on top of the plan's flags** — the gate has no models (Data Table uses the manual adapter with an in-memory collection), so Active Record would only add sqlite3 and a `db:prepare` per lane; bundle is skipped because lanes are separate Gemfiles; git is skipped because the app lives inside the monorepo.
2. **Only `Gemfile.herb` and `Gemfile.erubi` exist; `Gemfile.core`, `Gemfile.phlex`, `Gemfile.stable` are deferred to the phases that use them (3 and 5)** — writing a lane without running it would be untested config; Phase 0's acceptance only exercises herb and erubi. The shared part is `Gemfile.base`, eval'd by each lane.
3. **No plain `Gemfile`; `config/boot.rb` defaults `BUNDLE_GEMFILE` to `Gemfile.herb`** — the plan names the lanes explicitly and the gate lane should be what `bin/rails` runs by default.
4. **The initializer has three lines, not one** — the `RubyUI` inflection and the Zeitwerk collapse of `app/components/ruby_ui/*` are what the 1.6 installer already writes (`gem/lib/generators/ruby_ui/install/templates/ruby_ui.rb.erb`); `prepend_view_path("app/components")` remains the only line 2.0 adds. Registered on `on_load(:action_controller)` so it runs after Rails' own `add_view_paths` and `app/components` ends up first.
5. **`ReActionView.config.debug_mode = false`** — the plan does not mention it; the default (on in development) appends to `config.assets.precompile`, which propshaft does not define. `validation_mode = :raise` is what surfaces errors here anyway.
6. **`Base#render_in` is `render_in(view_context, **, &block)`, not `render_in(view_context, &block)`** — the pinned Rails ref passes `locals:` to renderables and deprecates the 1-arity form (`actionview/lib/action_view/template/renderable.rb` at `60eb5cb7…`). The caller's locals are not the component's; accepted and ignored.
7. **`attrs` keys are Strings (`attrs["class"]`) where the plan writes `attrs[:class]`** — the flat form the plan itself specifies is what `tag.attributes` consumes; the 1.6 reader (`PaginationItem`, Phase 4) changes `:class` to `"class"` when ported.
8. **The "renders nothing" layer probe uses a throwaway `Probes::Rootless`, not `DataTablePagination`** — the plan names `DataTablePagination` as the example but that class belongs to Phase 4 (days 6–8); the probe reproduces its shape (`total <= 1` → no root element) without pulling Data Table forward.
9. **Probe components and views live under `test/probes/components` and `test/probes/views/probe`, wired from `test/test_helper.rb` (view paths + `require`), not from app config** — keeps every test-only path out of `config/` and `app/`. The views got a prefix distinct from the components' (`probe/` vs `probes/`) because view paths are one flat namespace and a probe view named like a component sidecar shadowed it.
10. **Phlex's attribute guards and its nil-first `style:` spacing quirk are not reproduced in `RubyUI::Attributes`** — none of the 1.6 snapshots depend on them; listed in `LAYER.md` as a 2.0 decision rather than silently ported.
11. **System-test screenshots stay in `tmp/screenshots/` (gitignored)** — the plan says "saved as evidence, not compared"; committing PNGs into a throwaway app adds nothing the test log does not.
12. **`Time` is not in the attribute differential table (only `Date`)** — Phlex and the layer both call `iso8601`; the case adds timezone noise to a test meant to catch serialization differences, not clock ones.
13. **`Gemfile.tags` spike lane added on 2026-09-07 at the maintainer's request, outside the gate** — herb `main` (`4269f79f`) + prism git, for the experimental `ComponentTags::Visitor` (`<RubyUI::Dialog :open="true">…</RubyUI::Dialog>`), on Rails' own `ERB::Herb` handler via `config.action_view.erb_implementation`; no ReActionView. The plan forbids `main` in the gate (§7), so this lane is excluded from §3's criteria and from the go/no-go; its results are roadmap evidence for the decision document (`HERB_FINDINGS.md` rows 17–23). Additions: six `_tags` twin views, `config/initializers/component_tags.rb`, lane-aware tests. The herb and erubi lanes are untouched.
14. **The parity runner compiles a template with an unpinned render before the pinned one** — the pin is for ids a component mints while rendering; herb `main` draws `SecureRandom.hex(4)` at compile time (row 17) and shifted the counter. The plan's "active only while a scenario renders" is kept; compilation is not the scenario's render.

## Maintainer decisions

15. **2.0's authoring syntax is the Herb component tag: `<RubyUI::Dialog>…</RubyUI::Dialog>`** (maintainer, 2026-09-07). This closes the "kit-style sugar is a later API decision" left open by the plan (§2 item 9). Users write components as tags with the fully qualified constant — `<RubyUI::Dialog :open="true">`, `<RubyUI::DialogContent :size=":lg">`, `<RubyUI::Button variant="outline" class="rounded-full">Save</RubyUI::Button>` — and Herb's `ComponentTags::Visitor` (`ConstantResolver`) rewrites them at compile time into `render RubyUI::Dialog.new(open: true) do … end`. That `render RubyUI::X.new(...)` form stays the underlying, always-available API and is what the gate measures; the tags are a compile-time surface over it, so nothing in Phase 0–1 changes. Evidence: `experiments/v2-gate/app/views/gate/*_tags.html.erb`, six scenarios byte-identical to the 1.6 snapshots, system test green with the 1.6 controller (`HERB_FINDINGS.md` rows 18–21). Consequences the decision document (day 10) has to carry:
    - **Herb release dependency.** The visitor exists only on herb `main` (built from git with prism git), is marked experimental, and 0.10.3 has none of it. 2.0 now depends on the Herb release that ships component tags; until then, the tags lane stays a spike and the gate's verdict is still taken on 0.10.3 + ReActionView 0.4.0.
    - **ReActionView's role narrows.** The tags ran on Rails' own `ERB::Herb` handler (`config.action_view.erb_implementation`) with the visitor added; ReActionView 0.4.0 targets the 0.10.x engine and was not in that lane. Whether 2.0 needs ReActionView at all is now an open question for the Risks section.
    - **Attribute typing is an API decision still open** (row 19). A plain attribute is a String; Symbols, booleans and Hashes need the `:attr="ruby"` directive. Either components accept and coerce Strings (Button already does `to_sym`; `DialogContent::SIZES` does not) or the documentation teaches `:size=":lg"`. Decide before Phase 2 ports Select.
    - **No block parameter** (row 20): `yield(self)` components (ToggleGroup, ToastRegion) keep the ERB form `<%= render RubyUI::ToggleGroup.new do |group| %>`; the tag form cannot express them today. Phase 3 measures the ERB form.
    - **`class!`** (replace instead of merge) is not expressible as a tag attribute name; `class="…"` merges through tailwind_merge as in 1.6 and covers the restyle use case.
